# Hand of Elements
## Français
Hand of Elements est un projet de jeu de carte inspiré de Hearthstone et Magic the Gathering où l'on joue contre un autre joueur avec un deck de carte prédéfinie ou fait par le joueur.
Chaque carte possède un élément propre : Feu/Eau/Air/Terre et un effet. Certaines peuvent avoir des effets supplémentaires si la carte précédemment jouée est du même type.
Les joueurs peuvent poser des cartes sur le plateau et ces cartes peuvent soit attaquer d'autres cartes adverses, soit attaquer l'adversaire directement.
Ils peuvent également jouer des cartes sorts, qui auront un effet immédiat sur la partie. Par exemple : Infliger des dégâts, soigner ou donner un effet bénéfique ou néfaste sur un joueur ou une carte sur le terrain.
Les joueurs possèdent des points de vie, si ces points de vie tombent à 0, le joueur perd et son adversaire gagne la partie.

Ce jeu est un projet personnel fait pendant mes années d'études.
Mon but était de travailler avec le plugin Netcode pour pouvoir faire du multijoueur et aussi de pouvoir se connecter à des sessions créées par les joueurs et pouvoir jouer sur des réseaux différents.
Voici les éléments principaux/importants sur lesquels j'ai travaillé sur ce projet :
### Scriptable Objects
- Cela m'a permis de créer et éditer les données de mes cartes que les joueurs pourront jouer
- Un principe d'ID est utilisé pour envoyer les informations aux joueurs, les cartes seront automatiquement générées par ce simple ID que ce soit dans la main du joueur ou une fois posées sur son terrain.
### UI
- J'ai créé plusieurs outils de debug nécessaires pour pouvoir afficher les informations envoyées depuis le serveur à un client.
### Multijoueur
- Le système de connexion peut se faire de deux manières : Local et Online.
- - Le Local permet de créer une session simplement avec Netcode. Il permet de se connecter depuis un même ordinateur à une session lancée (principalement fait pour le développement)
- - Le Online utilise le Unity Relai (Unity Gaming Services). Il va, dans un premier temps, se connecter aux serveurs, puis générer un code temporaire que le client pourra rentrer une fois s'être connecté aux serveurs d'Unity pour pouvoir rejoindre la session.
- Les Network Variables sont beaucoup utilisés pour pouvoir synchroniser des valeurs importantes comme : Quel joueur peut jouer selon le tour, quelle carte le joueur a sélectionnée ou encore quel ID possède la carte.
- Le joueur est un objet important qui permet de faire le relai entre une action client et le serveur. Lorsqu'un objet doit exécuter du code du côté serveur, le joueur me permet de faire la passerelle.
### Managers
- Le jeu tourne principalement sur un Game Manager, j'y regroupe les passages des exécutions serveurs pour éviter de disséminer le code dans les divers composants.
- Le système d'effets des cartes ainsi que les sorts passent par un Spell Manager, il détermine les cibles et effectue les changements d'états ou de statistiques des cartes du côté serveur qu'il va transmettre automatiquement aux joueurs avec les Network Varaibles.

Ce que j'aimerais continuer et faire pendant ce projet
### IA
- Pouvoir jouer contre une IA avec plusieurs niveaux de difficultés.
### Multijoueur
- Ajouter des informations propres aux joueurs comme un pseudo en jeu, le nombre de parties et la victoire. Les données seront stockées directement sur l'ordinateur des joueurs puisque je n'ai pas de serveur qui pourrait garder ces informations.
- Un principe alternatif où les joueurs seront sélectionnés par rapport à un MMR. Même si la fonctionnalité ne sera pas implémentée, j'aimerais m'y renseigner.

## English
Hand of Elements is a card game project inspired by Hearthstone and Magic the Gathering where you play against another player with a predefined or player-made card deck.
Each card has its own element: Fire/Water/Air/Earth and an effect. Some may have additional effects if the card previously played is of the same type.
Players can put cards on the board and these cards can either attack other opposing cards or attack the opponent directly.
They can also play spell cards, which will have an immediate effect on the game. For example: Inflict damage, heal or give a beneficial or harmful effect on a player or card on the field.
Players have health points, if these health points drop to 0, the player loses and his opponent wins the game.

This game is a personal project made during my years of study.
My goal was to work with the Netcode plugin in order to be able to do multiplayer and also to be able to connect to sessions created by players and to be able to play on different networks.
Here are the main/important elements on which I worked on this project:
### Scriptable Objects
- This allowed me to create and edit the data from my cards that players can play.
- An ID principle is used to send information to the players; cards will be automatically generated by this simple ID, whether in the player’s hand or once placed on their field.
### UI
- I created several debug tools necessary to be able to display the information sent from the server to a client.
### Multiplayer
- The connection system can be done in two ways: Local and Online.
- - The Local allows you to create a session simply with Netcode. It allows you to connect from the same computer to a launched session (mainly done for development)
- - Online uses the Unity Relai (Unity Gaming Services). It will first connect to the servers, then generate a temporary code that the client can enter once connected to the Unity servers in order to join the session.
- Network Variables are used a lot to be able to synchronize important values such as: Which player can play according to the turn, which card the player selected or which ID the card has.
- The player is an important object that allows you to bridge the gap between a client action and the server. When an object needs to execute server-side code, the player lets me do the gateway.
### Managers
- The game runs mainly on a Game Manager, I group together passages from server executions to avoid spreading the code among the various components.
- The card effects system as well as the spells go through a Spell Manager, it determines the targets and makes changes to the server-side card states or statistics that it will automatically forward to players with the Network Varaibles.

What I would like to continue and do during this project
### AI
- Being able to play against an AI with several levels of difficulty.
### Multiplayer
- Add player-specific information such as an in-game username, the number of games, and victory. The data will be stored directly on the players' computers since I don’t have a server that could store this information.
- An alternative principle where players will be selected in relation to an MMR. Even though the feature will not be implemented, I would like to find out more about it.
